# Issa — Omar event staging audit (shipping Three.js, 2026-10-21)

Source review only. No runtime edit, browser playthrough, collision test, or Unreal work was performed.

## What the current build does

- The binding order is explicit in `src/npcData.ts:87-100`: café/Ravens, roots, amnesiac escape, found near mountain, cuffed transport to post, Moreno's assignment, then Elia on Day 2. `npcsAtDay` accepts only a complete ordered prefix (`src/npcData.ts:108-113`). Omar is admitted for the pre-attack café prefix (length 1) or after the found event (length 4+), and Elia needs Day 2 plus assignment (`src/npcData.ts:130-136`). The returned Omar stage switches among `cafe-before-attack`, `mountain-found`, and `police-post` (`src/npcData.ts:147-163`).
- Stage currently changes **the label, not the spot**. Omar's single base position is `(-15.0, SCHOOL_FLOOR, 47.5)` inside post [6] (`src/npcData.ts:223-235`). The stage mapping spreads that base spec without changing `position` (`src/npcData.ts:148-163`). `placeNpcs` resolves his footprint as the school and uses its authored floor (`src/npcPlacement.ts:29-41`); `makeActors` then takes those coordinates (`src/npcTalk.ts:165-185`). Thus a story state with event prefix 1 or 4 would put the supposed café/mountain Omar **inside the police post**. Those intermediate states are not presented by the normal current entry: `src/villageMain.ts:132-141` seeds Day 1 with the first five events, Day 2 with six, and `CH1_DAY1` describes discovery and transport as already past (`src/npcTalk.ts:21-23`). No visible discovery or escorted transport sequence exists in this entry path.
- Omar is marked seated as an actor only at `police-post` (`src/npcTalk.ts:185`); the actor collision box and chest target use seated or standing dimensions (`src/npcTalk.ts:194-202`). The Day 1 actor box is added to static `SOLIDS`, rather than `MOVING_ACTORS` (`src/villageMain.ts:147-151`). Visuals are built once for the actor list (`src/villageMain.ts:152`): the procedural Omar dress is **always seated** (`src/npcFigures.ts:81`), baked into the merged figure geometry (`src/npcFigures.ts:301-325`). The optional glTF uses the same role's target height and starts an Idle clip (`src/npcFigures.ts:339-375`), so an upright escort pose is not established there either. Contact shadow size derives from `a.seated` (`src/npcFigures.ts:379-382`). Cuffs are a separate prop, initially visible from `a.spec.cuffed` and updated with the actor (`src/npcFigures.ts:400-410,439-458`).
- Talkability is not separately disabled for Omar's intermediate stages. `nextLine` checks `talkable`, then the authored trigger conditions (`src/npcTalk.ts:25-49`). His Day 1 proposed line requires five events (`src/npcData.ts:236-245`), so at event prefix 1 or 4 he has no valid line, but he can still enter `TALKABLE_ACTORS` and `NPC_PICKS` (`src/villageMain.ts:156-165`). The look ray prioritizes static examinables, then NPC picks within 3.2 m through sight solids (`src/villageMain.ts:433-445`); E dispatches `talk` (`src/villageMain.ts:577-605`). At the normal Day 1 prefix 5, the seated, cuffed line is available; talking schedules the guarded medical check (`src/villageMain.ts:632-635`). Its timer removes cuff visibility and plays the release cue (`src/villageMain.ts:696-704`). Day 2 is seeded with `medicalCheckComplete`, and Omar's later line requires Elia's introduction flag (`src/villageMain.ts:132-140,637-646`).
- The authored school floor comes from `BUILDINGS` (`src/npcData.ts:4-7,232`; computed in `src/villageMap.ts:140-142,156-159`). This corrects the earlier underground position. The older `studio/npc/omar.md:16-17` still describes zero as temporary and has transport waypoints; those waypoints are specification, not a implemented escorted animation.

## Minimal event-gated path to implement later

1. Keep current Day 1 entry at event prefix 5 until a visible arrival is explicitly chosen. If intermediate states are exposed, make stage placement data for café and near-mountain discovery **only after their scene geometry and walkable floor are inspected**. Keep the post spot tied to event 5. At prefix 2 or 3, omit Omar entirely. No guessed upstairs elevation or mountain coordinate.
2. For prefix 1 and 4, set `talkable: false` on the returned stage spec. Build actor, collision, and pick lists from the same current stage. A future transition must update or rebuild static collision, visual pose/contact shadow, and pick registration together; moving only `a.x/y/z` would leave the old solid behind.
3. Add a standing/escorted figure configuration for café/discovery/transport and keep seated post pose at prefix 5. The current merged procedural geometry is baked once, so a standing-to-seated change needs a deliberate rebuild or a dedicated staged actor/pose path; toggling `a.seated` alone changes collision and chest height but not Omar's baked legs/chair. Similarly verify the glTF's actual animation clips and feet against the scene before relying on them.
4. On the guarded check, preserve the existing single cuff-release transition (`src/villageMain.ts:696-704`) and ensure subsequent Day 2 spawns remain uncuffed. Moreno's assignment remains off-screen after the transport/check chronology; no new spoken line is required. Proposed Arabic dialogue stays draft.

## Risks / decisions

- Event prefix 4 currently passes the `npcsAtDay` gate but places Omar inside the school; prefix 1 has the same mismatch. Do not expose those states as playable until position, pose, pick, collision, and visibility are stage-correct.
- `makeActors` drops any placement with issues (`src/npcTalk.ts:165-170`). Adding an unbuilt café upstairs coordinate could silently remove Omar, and changing a runtime position after the static solid has been added would desync navigation.
- The normal player sees only the post aftermath. Whether discovery and cuffed transport should be visible gameplay or an off-screen transition is still a presentation decision; the code must not imply those beats were already playable. The owner's fixed sequence and off-screen **Moreno assignment** remain binding either way.
- Source inspection establishes no rendered proof of seated alignment, cuff position, door clearance, or any new escort route. Do not assert those are visually correct without an actual playthrough.
